# 商品图册 · 需求分析与技术方案

> 版本：v1.1　日期：2026-10-29
> 项目目录：`D:\code\product-album`
> 技术路线：uni-app（Vue3 + Vite）→ 先跑 H5 → HBuilderX 打包 Android APK

---

## 1. 项目背景与目标

把各种商品的图片集中保存在一个 App 里，为每个商品设置"使用时长"（到期日），在临近到期时通过系统通知提醒自己重新购买/续费。

**一句话定义**：一个离线优先的"商品图片 + 到期提醒"管理工具。

**设计原则**：

1. **离线优先**：不依赖服务端，断网也能增删改查、也能按时提醒。
2. **数据不丢**：图片和商品数据全部落地到本机，App 升级不清数据。
3. **提醒可靠**：App 被杀掉后，Android 端仍能按时间弹出系统通知。
4. **一套代码两端跑**：H5 用于日常调试和电脑端使用，APK 用于手机日常使用。

## 2. 需求确认（2026-10-29 已与用户确认）

| 问题               | 用户选择                  | 对设计的影响                                                                                                                                       |
| ------------------ | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| App 给谁用         | **自己用的工具**          | 不做防破解、不做服务端时间校验、不做设备绑定；到期只提醒不锁定                                                                                     |
| 图片怎么进 App     | **App 内从相册/文件导入** | 需要做"运行时图片持久化"：H5 用 IndexedDB，App 用私有目录；APK 内不预置商品图                                                                      |
| 到期后的行为       | **只提醒，不限制查看**    | 不需要图片加密/加锁逻辑，数据模型可以简化                                                                                                          |
| App 关闭后是否提醒 | **要，系统通知栏提醒**    | 必须写 Android 原生能力（UTS 插件 + AlarmManager + NotificationManager），`plus.push.createMessage` 的 `delay` 不足以覆盖"进程被杀"场景（见 §8.2） |

## 3. 核心使用场景

1. **录入**：买了 5 张商品图/某个图片包 → 打开 App → 新建商品 → 从相册选图 → 填购买日期和使用时长（如 90 天）→ 保存。
2. **查看**：平时打开 App 看某商品的图片、剩余天数。
3. **提醒**：距离到期 7 天时手机弹通知"XX 商品还有 7 天到期，记得续费"；到期当天再提醒一次。
4. **续费**：点通知进入详情 → 点"续费" → 选续费时长 → 到期日顺延 → 留下一条续费记录。
5. **回顾**：看哪些已过期、哪些即将到期、总共花了多少钱。

## 6. 数据模型

数据统一存 `uni.setStorageSync`（H5 落 localStorage，App 落 plus storage），图片二进制单独存（见 §7.3）。

### 6.1 Product（商品）

```js
{
  id: 'p_xxx',                    // 唯一 ID
  name: '商品名称',
  category: '分类名',
  tags: ['标签1', '标签2'],
  note: '备注',
  images: [                        // 图片引用，最多 20 张
    { id: 'img_xxx', w: 1080, h: 1080, size: 123456 }
  ],
  coverIndex: 0,                   // 封面取 images[coverIndex]
  purchaseDate: '2026-10-01',      // 购买日期 YYYY-MM-DD
  durationValue: 90,               // 时长数值
  durationUnit: 'day',             // day | month | year
  expiryDate: '2026-12-30',        // 派生字段，冗余存储便于列表排序
  reminderDays: -1,                // -1 = 跟随全局设置
  renewals: [                      // 续费记录
    { id: 'r_xxx', date: '2026-12-20', value: 30, unit: 'day', amount: 99, note: '' }
  ],
  createdAt: 1760000000000,
  updatedAt: 1760000000000
}
```

### 6.2 AppSettings（全局设置）

```js
{
  schemaVersion: 1,
  defaultReminderDays: 7,          // 默认提前 7 天
  notifyTime: '09:00',             // 每天提醒时间点
  notifyEnabled: true,
  theme: 'auto',                   // auto | light | dark
  lastBackupAt: 0
}
```

### 6.3 NotifyRecord（通知去重记录）

```js
{
  'p_xxx|2026-12-30|7': 1760000000000   // key = 商品ID|到期日|提前天数 → 已发送时间
}
```

### 6.4 到期计算规则

- **按天**：`expiry = purchaseDate + N 天`
- **按月**：`expiry = purchaseDate + N 个月`，目标月没有对应日时取该月最后一天（1/31 + 1 月 = 2/28；闰年 2/29）
- **按年**：同上，2/29 + 1 年 = 次年 2/28
- **到期日当天算最后一天**：`剩余天数 = expiryDate - 今天`，结果为 0 表示"今天到期"，`< 0` 表示已过期
- **续费顺延**：未过期时从原 `expiryDate` 往后加；已过期时从今天往后加（避免续费后仍是过期状态）

### 7.3 图片存储方案（关键）

| 平台 | 保存                                                  | 读取                                         | 删除                                     |
| ---- | ----------------------------------------------------- | -------------------------------------------- | ---------------------------------------- |
| H5   | `uni.chooseImage` → canvas 压缩 → Blob 写入 IndexedDB | 从 IndexedDB 取 Blob → `URL.createObjectURL` | 删除 IndexedDB 记录                      |
| App  | `uni.chooseImage` → `uni.saveFile` 复制到 `_doc/`     | 直接用 `savedFilePath`                       | `plus.io.resolveLocalFileSystemURL` 删除 |

统一接口：

```js
// services/imageStore.js
export async function importImages(tempFilePaths) // → [{id, w, h, size}]
export async function resolveImageUrl(imageId)    // → 可显示的 URL
export async function removeImage(imageId)
export async function exportImageBase64(imageId)  // 备份用
```

> H5 端 `URL.createObjectURL` 产生的地址只在当前页面生命周期有效，**不能持久化这个 URL**，持久化的只能是 imageId。

### 7.4 通知方案（关键）

**需求**：App 完全关闭时，到点仍能收到通知。

**结论**：`plus.push.createMessage` 只能立即或在 App 进程存活期间延迟显示，无法在进程被杀后定时触发（见 §8.2 验证）。因此需要**原生定时能力**。

**方案**：编写 UTS 插件 `helper-alarm`：

```
uni_modules/helper-alarm/
├── package.json
└── utssdk/
    ├── interface.uts          # 对外 API 声明
    └── app-android/
        ├── index.uts          # Kotlin 实现
        └── config.json        # 声明权限、Receiver
```

对外 API：

```ts
requestNotificationPermission(): boolean
schedule(id: string, triggerAt: number, title: string, content: string, payload: string): void
cancel(id: string): void
cancelAll(): void
```

内部实现要点：

1. `AlarmManager.setExactAndAllowWhileIdle()` 定时（Android 12+ 需 `SCHEDULE_EXACT_ALARM`，或退化为 `setAndAllowWhileIdle`）
2. `PendingIntent` 指向插件内声明的 `BroadcastReceiver`
3. Receiver 收到后调用 `NotificationManager.notify()`，通知渠道 `product-album-reminder`
4. 通知点击 `PendingIntent` 打开 App 并带上 `productId`，详情页据此跳转
5. 监听 `BOOT_COMPLETED` 在重启后重排（可选，第二期）

**降级策略**：

- H5：仅页面打开时用 Web Notification + 页面内横幅提醒
- App 未授权通知权限：降级为启动时弹窗提醒

**排程策略**：

- 每次 App 启动、数据变更（新增/编辑/续费/删除）、设置变更后，**全量重排**未来 60 天内的提醒点（先 `cancelAll` 再逐条 `schedule`）
- 提醒点生成：每个商品生成 `到期日 - reminderDays` 和 `到期日` 两个时间点，时间取设置里的 `notifyTime`

### 7.5 页面与交互

- **底部 TabBar**：首页 / 日历 / 设置
- **首页**：顶部统计卡（总数、30 天内到期、已过期）→ 筛选 Chip（全部/即将到期/已过期）→ 商品卡片网格（封面 + 名称 + 剩余天数 + 进度条）
- **详情**：图片轮播（可点开大图）→ 商品信息 → 到期倒计时 → 续费按钮 → 续费历史 → 编辑/删除
- **编辑**：表单 + 图片九宫格 + 日期选择 + 时长输入 + 提醒天数
- **设置**：默认提前天数、提醒时间、通知权限状态、数据导出/导入、深色模式、关于

### 7.6 打包方案

1. 用 HBuilderX 打开项目目录（`文件 → 导入 → 从本地目录导入`）
2. 登录 DCloud 账号，在 `manifest.json` 的可视化界面获取 AppID
3. `发行 → 原生 App - 云打包 → Android`，使用 DCloud 公共测试证书（自用足够）
4. 产出 APK 安装到手机

> 本机当前**没有 JDK、Android SDK**，所以不走离线打包。云打包在 DCloud 服务器完成，无需本地环境。
> HBuilderX 当前是标准版，首次运行 uni-app / 云打包时会提示安装 `uni-app 编译器`、`App 云打包` 等插件，按提示安装即可。

### 8.2 plus.push 定时通知（推断，待真机验证）

- `plus.push.createMessage(content, payload, options)` 的 `options.delay` 单位是**秒**，只控制消息延迟显示。
- 多方资料指出：本地消息依赖 App 进程存活，进程被杀后不会触发；真正的离线推送需要 uniPush + 厂商通道或原生定时。
- 结论：**不把 `plus.push` 作为"App 关闭后提醒"的主方案**，只作为 App 在后台时的即时通知补充。
- 官方文档 `https://www.html5plus.org/doc/zh_cn/push.html` 在本机网络环境无法访问（WebFetch 被拦截），上述结论来自搜索结果，标记为**待真机验证**。

### 8.3 UTS 插件可行性（部分实测）

- HBuilderX 5.34 CLI 自带 `compile app-android` 命令，说明该版本支持 UTS 插件编译（`cli.exe help` 实测）。
- 云打包时 UTS 插件由 DCloud 服务器编译，本机不需要 Android SDK（待实际打包验证）。
- 风险：标准版 HBuilderX 可能未安装 UTS 编译器插件，首次编译会提示下载。

## 10. 风险与对策

| 风险                     | 影响                | 对策                                                           |
| ------------------------ | ------------------- | -------------------------------------------------------------- |
| UTS 插件编译/云打包失败  | 无法实现关闭后通知  | 先做启动检查兜底；插件失败时降级用 `plus.push` + 后台定时器    |
| Android 厂商杀后台       | AlarmManager 被延迟 | 用 `setExactAndAllowWhileIdle`；引导用户在系统设置里允许自启动 |
| H5 localStorage 5MB 限制 | 图片存不下          | 图片走 IndexedDB，元数据才走 localStorage                      |
| 用户改系统时间           | 提醒时间不准        | 自用工具，不处理；到期日按本地日期计算                         |
| 图片体积过大             | 存储占用高、列表卡  | 导入时压缩到最长边 1600px + 生成缩略图                         |
| HBuilderX 标准版缺插件   | 无法编译 App        | 按提示安装 uni-app 编译器、云打包插件，或换 App 开发版         |

### 12.3 UTS 编译过程中修正的问题

1. `AlarmReceiver::class.java` 不被 UTS 接受，报 `Expected ',', got ':'`（`index.uts:186`）→ 改为 `UTSAndroid.getJavaClass(AlarmReceiver)`。
2. `interface.uts` 里声明 `export function ...` 触发编译器 panic：
   `internal error: entered unreachable code: overload error getPermission != requestPermission`
   → 删除函数声明、只保留 `PermissionCallback` 类型后，转换阶段通过。
3. `uts-development-android` 插件依赖 `amazon-corretto`、`uniapp-runextension`，已用 `cli.exe installPlugin --force true` 安装；但完整编译仍需要 Android SDK 环境，本机没有。

### 13.2 提醒可靠性修复

1. 通知权限被拒时不再误记为已提醒。
